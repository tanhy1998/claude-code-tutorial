Frontmatter you'll use

FieldDoes
nameThe /command. Defaults to the folder name
descriptionWhat it does + "Use when …". Always in context; Claude matches on it. Capped at 1,536 chars, so put the use case first
argument-hintAutocomplete hint, e.g. "[table name]"
argumentsNames for positions: [issue, branch] → $issue, $branch
disable-model-invocationtrue = only you can run it; description not in context
user-invocablefalse = only Claude can run it; hidden from / menu
allowed-toolsPre-approves tools for the invoking turn. Doesn't restrict anything
disallowed-toolsRemoves tools while the skill is active
shellbash (default) or powershell for !`…` lines
pathsGlobs: Claude only auto-loads it when working on matching files
model, effort, context: fork, agent, hooksLater lessons (subagents, hooks)

Unknown fields are ignored without warning. Opening line not exactly --- → no frontmatter.

Dynamic context: !`cmd` rules

  1. Runs at invocation, every invocation. Claude only sees the output.
  2. Non-zero exit → the whole invocation aborts. Append || true to tolerate it.
  3. Goes through permission checks. Outside auto mode, a command that isn't pre-approved aborts it. Tested: silent, with the reason only in claude --debug as Shell command permission check failed for command in /name.
  4. Tested (PowerShell, manual mode): Test-Path and Select-String with literal paths ran without approval. New-Guid needed allowed-tools. Wildcard paths, [type]::Method() calls, and { script blocks } were refused even with allowed-tools.
  5. Turn it off everywhere with the setting "disableSkillShellExecution": true.

Lifecycle

  • Once invoked, the rendered text stays in the conversation. It isn't re-read, so edits apply from the next invocation.
  • After compaction, the first 5,000 tokens of each recent skill come back (25,000 total). Put the key steps first, and re-invoke if it drifts.
  • A rule that must hold every time belongs in a hook, not a skill step.
