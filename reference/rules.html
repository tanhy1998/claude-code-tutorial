One page. Source: code.claude.com/docs/en/memory (checked 2026-10-15, Claude Code v2.1.300).

Locations

WhereApplies to
.claude/rules/**/*.mdThis project; committed, so it reaches the team. Subfolders are scanned too.
~/.claude/rules/*.mdYou, in every project. Loads before project rules; neither overrides the other.

Load rules

  1. No paths → loads at launch, like .claude/CLAUDE.md. Organises, doesn't save context.
  2. With paths → loads when Claude Reads, Writes, or Edits a matching file, or views one with a single-file cat/head.
  3. Broken YAML → frontmatter is ignored, so the rule loads every session. Check with claude --debug. The error goes to the log file ~\.claude\debug\<session>.txt, not the screen: [WARN] Failed to parse YAML frontmatter: … Unresolved alias. A first line that isn't exactly --- (e.g. \--- from an editor that escapes markdown) means no frontmatter at all.
  4. After /compact → path rules return only on the next matching file.
  5. Still context, not enforcement. Conflicting rules → Claude may pick one arbitrarily.

Syntax

.claude/rules/tmdl.md---
paths:                                  ← the ONLY field rules read; others ignored
  - "**/*.tmdl"                         ← ALWAYS quote: a leading * is YAML alias syntax
  - "**/*.{pbism,pbir}"                 ← brace expansion = several patterns
---

# TMDL rules
- One checkable instruction per line

Also accepted: a comma-separated string, e.g. paths: "**/*.tmdl, **/*.pbism".
