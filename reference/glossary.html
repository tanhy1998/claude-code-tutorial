Glossary

The course uses these words with exactly these meanings. Terms are added as lessons introduce them.

TermMeaningLesson
Context windowEverything Claude can see in a session: system prompt, memory files, conversation, tool results. Each session starts with a fresh one.1
Memory fileA file Claude Code loads into context for you: CLAUDE.md, CLAUDE.local.md, AGENTS.md, rule files. Listed under Memory files in /context.1
CLAUDE.mdInstructions you write that Claude reads at the start of every session. Context, not enforcement.1
Auto memoryNotes Claude writes for itself from your corrections. Not covered yet.1
ScopeWho an instruction reaches and where: managed (org), user (you, all projects), project (team via git), local (you, this project).1
AGENTS.mdCross-tool instruction file. Claude reads it only when there's no CLAUDE.md, unless CLAUDE.md imports it with @AGENTS.md.1
Import@path inside a memory file. Pulls another file in at launch. Organises, but doesn't save context.1
Context vs enforcementContext is text Claude chooses to follow (CLAUDE.md, rules, skills). Enforcement is something the harness makes happen regardless (hooks, permissions).1
RuleA markdown file in .claude/rules/ (or ~/.claude/rules/). Without paths, it behaves like CLAUDE.md.2
Path-scoped ruleA rule with paths: frontmatter. It loads only when Claude reads, writes, or edits a matching file.2
FrontmatterThe YAML block between --- lines at the top of a markdown file. It's configuration that Claude Code removes before the file reaches Claude.2
GlobA file-matching pattern. * = any characters within one folder; **/ = any depth of folders; {a,b} = either.2
On-demand loadingA memory file that isn't loaded at launch, but only once Claude touches a relevant file (path rules, subdirectory CLAUDE.md).2
CanaryA temporary, harmless instruction (e.g. "end replies with (tmdl rule)") whose visible effect proves a file loaded.2
Settings fileA JSON config file Claude Code reads (not Claude): managed, --settings, .claude/settings.local.json, .claude/settings.json, ~/.claude/settings.json, from highest precedence to lowest.3
PrecedenceWhich file wins when several set the same single value. Lists merge instead. Permission rules ignore precedence: a deny from any file wins.3
Permission ruleTool or Tool(specifier) in an allow, ask, or deny list. Checked deny → ask → allow; the first match wins. Enforced by Claude Code.3
Permission modeThe baseline for what runs without a prompt: Manual (default), acceptEdits, plan, auto, dontAsk, bypassPermissions. Rules sit on top of it.3
Auto mode / classifierA mode in which a second model (the classifier) reviews shell and network actions instead of asking you. Reads and in-folder edits are auto-approved. The built-in default since v2.1.283.3
Anchored patternA path rule that matches only at one location (e.g. .pbi/cache.abf = launch folder only), as opposed to any depth (**/.pbi/cache.abf, or a bare file name).3
Protected pathA path whose writes are never auto-approved, except in bypass mode: .git, .claude, .vscode, .mcp.json, shell rc files…3
Workspace trustThe "trust this folder?" dialog. A repo's allow rules and settings-file hooks wait for it; deny/ask rules don't. claude -p skips the dialog and treats the folder as trusted.3, 5
SkillA folder with a SKILL.md: frontmatter plus a procedure. Its description is always in context. The body loads only when invoked (/name, or Claude matching the description).4
InvokeLoad a skill's body into the conversation, either by you typing /name or by Claude choosing it. The text then stays put and isn't re-read.4
Invocation controlWho may invoke a skill: disable-model-invocation: true = you only (description hidden from Claude); user-invocable: false = Claude only.4
Dynamic context injectionA !`command` line in a skill. Claude Code runs it before Claude reads the skill and pastes in the output. Failures and unapproved commands abort the invocation.4
Argument placeholder$ARGUMENTS (all), $0/$1… (one each), $name (named). Any $ + digit is a placeholder; escape a literal with \$.4
Supporting fileAny other file in a skill's folder. It loads only when SKILL.md sends Claude to read it.4
HookA command (or HTTP call, prompt, agent) that Claude Code runs at a fixed lifecycle event. Enforcement, not context: it runs whether or not Claude would choose to.5
Hook eventThe lifecycle point a hook is attached to: PreToolUse, PostToolUse, SessionStart, Stop, InstructionsLoaded…5
PreToolUseThe event after Claude picks a tool call and before it runs, ahead of permission rules and modes. Exit 2 blocks the call.5
MatcherThe hook-group filter on tool name: Edit|Write|PowerShell. Case-sensitive. Other characters turn it into a regex.5
Exec form / shell formExec form: command + args, with the .exe spawned directly. Shell form: command only, run by Git Bash or PowerShell (shell).5
Fail open / fail closedWhat a guard does when it breaks itself. Open = the action goes ahead (the PreToolUse default for crashes). Closed = it's blocked ("onFailure": "block").5
PostToolUseThe event right after a tool call succeeds. It can't block or undo anything. Exit 2 sends your stderr to Claude so it can fix what the tool did.6
BOMByte order mark: the bytes EF BB BF at the start of a UTF-8 file. PBIP files must not have one. UTF-16 files start with FF FE.6
CRLF / LFWindows line endings (\r\n) vs Unix (\n). Power BI Desktop writes CRLF, so mixing in LF makes noisy diffs.6
