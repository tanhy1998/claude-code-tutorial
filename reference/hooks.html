Hooks

One page. Sources: hooks guide and hooks reference (checked 2026-10-18, Claude Code v2.1.302). Lines marked tested are from my own runs on that version, on Windows PowerShell 5.1.

Where a PreToolUse hook sits

Claude picks a tool call → PreToolUse hooks (exit 2 = block, stderr → Claude) → permission rules deny → ask → allow → permission mode → tool runs → PostToolUse hooks (can't undo; Lesson 6)
  • A hook block beats every mode, including bypassPermissions. Tested.
  • A hook's "allow" doesn't beat a deny rule. Hooks only tighten.
  • Skill !`…` lines aren't tool calls, so PreToolUse doesn't see them. Tested.

Config shape (in any settings file)

"hooks": {
  "PreToolUse": [
    { "matcher": "Edit|Write|PowerShell|Bash",
      "hooks": [
        { "type": "command",
          "command": "powershell.exe",
          "args": ["-NoProfile", "-ExecutionPolicy", "Bypass", "-File",
                   "${CLAUDE_PROJECT_DIR}/.claude/hooks/NAME.ps1"],
          "onFailure": "block" } ] } ] }
FieldDoes
matcherTool names, case-sensitive. A|B or A, B = exact names. Any other characters make it a regex, so Edit.* also matches NotebookEdit
ifOne permission-rule pattern to narrow it further, e.g. "Edit(**/*.tmdl)". Tested: Edit(…) here fired for Edit but not for Write. Best effort, so don't use it to enforce anything
command + argsExec form: spawns the .exe directly, with no shell and no quoting worries
command alone (+ shell)Shell form: Git Bash by default on Windows; "shell": "powershell" to switch
onFailure"block": a crash, timeout, or exit other than 0/2 blocks the call (v2.1.295+)
timeoutSeconds. Default 600 for command hooks

Where to find tool names for a matcher

  • Built-in tools: the table in the Tools reference. Its names are the exact strings you use in permission rules, subagent tool lists, and hook matchers.
  • MCP tools: mcp__<server>__<tool>. Run /mcp to see exact names. Matching a whole server needs the .*: mcp__powerbi__.* works, but mcp__powerbi matches nothing (matcher patterns).
  • This session: ask What tools do you have access to? The set depends on platform, model, and settings.
  • What Claude actually calls: use the tool_name field in the hook's stdin. A "*" matcher that logs it shows you every tool Claude uses.

Tools that can change a file: Edit · Write · NotebookEdit · PowerShell · Bash · Monitor (runs commands; uses the same rule format as Bash) · any MCP tool that writes. Matchers take bare names. Edit(…) belongs in if or in permissions, never in matcher.

Locations: ~/.claude/settings.json (you) · .claude/settings.json (team) · .claude/settings.local.json (you, this repo) · plugin hooks/hooks.json · skill or agent frontmatter. A handler that's the same in several settings files runs once.

Exit codes (PreToolUse)

ExitCallMessage
0Continues to the normal permission flowstderr is never shown to Claude
2Blockedstderr → Claude as the reason
otherContinues (non-blocking error), unless onFailure: "block"hook error notice, first line of stderr

JSON form (exit 0, stdout): {"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "deny", "permissionDecisionReason": "…"}}. The values are allow, deny, ask, and defer (-p only). Pick exit 2 or JSON, not both.

Exit codes (PostToolUse)

Fires only after a tool succeeds. It can't block or undo: the file is already on disk. Tested on v2.1.303.

ExitEffect
0Nothing reaches Claude
2stderr → Claude, next to the tool result. Use this to make Claude fix what the tool did
otherA notice for you. Claude sees nothing (tested)

No onFailure: it only matters for blocking. Shell commands don't name their files, so ask git: git -c core.quotepath=off status --porcelain --untracked-files=all -- '*.tmdl'. Check the bytes on disk: with autocrlf, git stores LF.

Also in the input: tool_name, cwd, permission_mode, session_id, transcript_path. In PowerShell: $call = [Console]::In.ReadToEnd() | ConvertFrom-Json.

Windows PowerShell 5.1 traps (all tested)

  1. Errors don't stop a script by default, so a broken parse can exit 0. Put $ErrorActionPreference = "Stop" first and set onFailure: "block".
  2. Shell form & "script.ps1" turns the script's exit 2 into status 1. Use exec form with -File.
  3. A typo in the -File path shows as finished with status 0, so it fails open even with onFailure. Re-test the block after every config change.
  4. Keep scripts ASCII. 5.1 reads a BOM-less .ps1 as ANSI.
  5. Write the reason with [Console]::Error.WriteLine("…"). Write-Error wraps it in noise.
  6. Never put a bare $CLAUDE_PROJECT_DIR in a shell-form PowerShell command, because it resolves to $null. Use ${CLAUDE_PROJECT_DIR} or $env:CLAUDE_PROJECT_DIR.

Test and debug

# unit test, no Claude: pipe JSON in, read the exit code
'{"tool_name":"Edit","tool_input":{"file_path":"C:\\x\\a.tmdl"}}' |
  powershell -NoProfile -ExecutionPolicy Bypass -File .claude\hooks\NAME.ps1; $LASTEXITCODE

/hooks                                # in Claude: is it listed, under the right event?
claude --debug-file hooks.log         # then search: "Hooks: PreToolUse"
                                      # → "… finished with status 2 (480ms)"

If /hooks shows nothing: check the JSON is valid (no trailing commas or comments) and the file location, then restart the session. Settings-file hooks don't run in an interactive session until the folder is trusted. In claude -p, a repo's hooks run without asking.

The lab's hooks

lab\.claude\hooks\block-unapplied.ps1$ErrorActionPreference = "Stop"
$call = [Console]::In.ReadToEnd() | ConvertFrom-Json
$target = if ($call.tool_input.file_path) { $call.tool_input.file_path } else { $call.tool_input.command }
if ($target -notmatch '\.tmdl|\.SemanticModel[\\/]definition') { exit 0 }
$pending = Get-ChildItem "$env:CLAUDE_PROJECT_DIR\*.SemanticModel\.pbi\unappliedChanges.json" -ErrorAction SilentlyContinue
if (-not $pending) { exit 0 }
[Console]::Error.WriteLine("Blocked by hook: … Ask the user to apply or discard the pending changes in Power BI Desktop first.")
exit 2

PostToolUse: lab.claudehookscheck-tmdl.ps1 (Lesson 6) reports UTF-16, BOM, ANSI, and LF in any changed .tmdl and exits 2.

Why the PreToolUse one: Desktop overwrites external query edits when it applies unappliedChanges.json (Microsoft Learn).
