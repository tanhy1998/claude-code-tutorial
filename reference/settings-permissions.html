Settings & permissions

One page. Sources: settings, permissions, permission modes (checked 2026-10-18, Claude Code v2.1.302).

Files, highest precedence first

#FileReaches
1Managed (managed-settings.json, MDM, claude.ai console)Your org. Can't be overridden.
2claude --settings <json|file>This session
3.claude/settings.local.jsonYou, this repo. Gitignore it yourself if you created it by hand.
4.claude/settings.jsonThe team, via git
5~/.claude/settings.json (%USERPROFILE%\.claude)You, every project
  • Single values (e.g. model): the highest file wins. Lists (allow/ask/deny): merged.
  • A deny from any file beats an allow from any file.
  • Strict JSON: no comments, no trailing commas. Changes reload live. Check with /status (Setting sources) and /permissions (rule + source file). Rejected entries: claude doctor.
  • Project allow rules wait for workspace trust. deny/ask apply immediately.

Rule syntax

{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "permissions": {
    "deny":  ["Read(**/.pbi/cache.abf)", "Edit(.pbi/**)"],
    "ask":   ["Edit(**/*.Report/definition/report.json)"],
    "allow": ["Bash(git add *)", "PowerShell(git add *)"]
  }
}
  1. Checked in the order deny → ask → allow. First match wins. Specificity doesn't matter.
  2. Tool = every use; Tool(specifier) = matching uses. A bare Bash deny removes the tool.
  3. File rules: use only Read(…) and Edit(…). Write(…)/Glob(…) path rules are never consulted.
  4. A Read deny also blocks Edit/Write on that path and hides the file from Glob.
  5. Shell: Bash(git log *). Put the * after the subcommand. PowerShell(Get-ChildItem *) also matches aliases (ls, dir).

Modes

  • Shift+Tab cycles modes. --permission-mode <mode> sets one at launch. permissions.defaultMode sets the default.
  • Deny rules apply in every mode. Ask rules prompt even in auto and bypass.
  • auto/bypassPermissions in project or local settings don't take effect.
  • Protected paths (.git, .claude, .vscode, .mcp.json…): writes are never auto-approved, except in bypass mode. Allow rules don't change that.

Limits

  • Read/Edit denies cover built-in file tools, recognized Bash file commands (cat, head, sed, tee), and redirects. PowerShell Get-Content was also blocked in testing on v2.1.302. They don't cover scripts that open files themselves, or grep -r ..
  • Bash rules match command text: Bash(git push *) doesn't stop git -C . push. Not a security boundary.
  • Windows: a Bash(…) deny turns off the PowerShell tool unless you add a matching PowerShell(…) rule.
