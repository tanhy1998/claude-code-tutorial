Lesson 1 · Memory

CLAUDE.md: brief Claude on your PBIP repo once

So no teammate ever has to type "don't touch diagramLayout.json" into a chat again.

~45 min (15 of it is one-time lab setup)Hands-on: terminal + Power BI DesktopPrimary source: How Claude remembers your project
Why this, first Your mission is a PBIP workflow your team shares through git. Every other feature in this course (rules, skills, hooks, MCP, agents) sits on one base: the instructions Claude reads at the start of every session. The official docs say the same thing: New to Claude Code? Start with CLAUDE.md for project conventions (features overview).

Your win today: a hand-written, committed CLAUDE.md in a real PBIP repo. You'll see that Claude follows it: it adds a measure to your TMDL, Power BI Desktop applies the change, and Claude refuses to edit a file you've ruled off-limits.

Part A: Build the lab (one time)

You'll practise in a dummy PBIP project at claude-code-tutorial\lab\. I've already generated the data: four CSVs in lab\data\ (Sales: 20,000 rows from 2024–2025; Products: 46; Customers: 600; Stores: 8 across Malaysian regions). You know Power BI, so this part is brief.

  1. In Power BI Desktop: File › Options › Preview features. Turn on Detect and reload external PBIP changes (needs the August 2026 release or later), then restart Desktop.This is what lets Desktop notice files that Claude edits and offer Apply external changes. MS Learn: Edit PBIP files outside Desktop. If the TMDL or PBIR storage options also appear there, make sure they're on.

  2. New report → load the four CSVs → build a star schema: Sales joined to Products, Customers, and Stores on their IDs. Add a DAX Date table, mark it as a date table, and turn off Auto date/time for this file.

  3. Create a measures table with 3 or 4 measures (e.g. Total Sales, Total Quantity, Gross Margin %). Build one report page with a card and a bar chart. Ten minutes is enough; it's a lab.

  4. File › Save as › Power BI project (.pbip) into the lab folder. Name it Contoso. You should end up with Contoso.pbip, Contoso.SemanticModel\, Contoso.Report\ and a .gitignore.

  5. Make the lab a git repo and commit a baseline. Microsoft recommends committing a baseline before letting an agent edit PBIP files, and setting autocrlf because Desktop writes CRLF line endings.Baseline advice: Report Authoring skill: Considerations. CRLF and autocrlf: PBIP considerations.

    cd $HOME\Desktop\Claude\claude-code-tutorial\lab
git init
git config core.autocrlf true
git add .
git commit -m "Baseline PBIP from Power BI Desktop"

Part B: What CLAUDE.md is (and isn't)

1. Every session starts from zero

Each Claude Code session begins with a fresh context window. CLAUDE.md files are instructions you write to give Claude persistent context, and they're loaded at the start of every session.Memory docs, opening section. The other mechanism there, auto memory, is notes Claude writes for itself. You write CLAUDE.md; Claude writes auto memory. The docs put the test simply: write down what you'd otherwise re-explain. Add a line when Claude makes the same mistake twice, when review catches something Claude should have known, or when a new teammate would need the same context.

2. It's context, not enforcement

This is the most important idea in the lesson. Claude treats them as context, not enforced configuration. To block an action regardless of what Claude decides, use a PreToolUse hook instead.Memory docs: CLAUDE.md vs auto memory. The features overview says it more bluntly: An instruction like "never edit .env" in CLAUDE.md or a skill is a request, not a guarantee. In PBIP terms, "never edit diagramLayout.json" in CLAUDE.md is a strong request. In Lesson 5 you turn it into a hard block.

3. Four scopes, four files

Ask two questions about any instruction: who should get it, and which projects it applies to. The answers pick the file.

ScopeLocation (Windows)Shared withPBIP example
Managed policyC:\Program Files\ClaudeCode\CLAUDE.mdEveryone in the org (deployed by IT)"Never paste customer data into prompts."
User~\.claude\CLAUDE.mdOnly you, in every project"Explain DAX changes in one sentence; I'm advanced."
Project.\CLAUDE.md or .\.claude\CLAUDE.mdThe team, via git"Measures live in _Measures; always set a format string."
Local.\CLAUDE.local.md (add it to .gitignore)Only you, in this project"My dev workspace is Contoso-Dev-Mine."

Source: Choose where to put CLAUDE.md files. The table lists scopes from broadest to most specific, which is also the order they appear in context.

4. How they load

At launch, Claude Code loads CLAUDE.md and CLAUDE.local.md from the directory you started in and every directory above it. The files don't override each other. They're concatenated, from the filesystem root down to your working directory, so the files nearest to where you launched are read last. In each directory, CLAUDE.local.md comes after CLAUDE.md. A CLAUDE.md in a subdirectory doesn't load at launch. It loads the first time Claude reads or edits a file in that subdirectory.How CLAUDE.md files load. When two instructions contradict each other, Claude may pick one arbitrarily, so remove conflicts rather than relying on order.

~\.claude\CLAUDE.md ← user scope: loads at launch, in every project Desktop\Claude\claude-code-tutorial\ ← a CLAUDE.md here would ALSO load (ancestor) └─ lab\ ← you run `claude` here ├─ CLAUDE.md ← project scope: loads at launch, committed ├─ CLAUDE.local.md ← local scope: loads at launch, after CLAUDE.md, gitignored ├─ Contoso.SemanticModel\ │ └─ CLAUDE.md ← loads on demand: when Claude touches a file in here └─ Contoso.Report\

5. Writing it well

  • Make every instruction checkable. The docs contrast "Use 2-space indentation" with "Format code properly". For PBIP: "Save TMDL as UTF-8 without BOM" rather than "be careful with encoding".
  • Keep it under 200 lines. Longer files cost context on every request and reduce adherence. @path/to/file imports help you organise, but they don't save context, because imported files load at launch too (max depth: four hops).Write effective instructions · Import additional files. Instructions that matter for only part of the repo belong in path-scoped rules. That's Lesson 2.
  • Leave notes for humans for free. Block-level <!-- HTML comments --> are stripped before the file reaches Claude. Use them for "why" notes and source links.
  • Keep procedures out. A multi-step procedure, like a publish checklist, belongs in a skill (Lesson 4), not in CLAUDE.md.

6. The commands you'll use

CommandWhat it does
/initAnalyses the repo and writes a starter CLAUDE.md. If one exists, it suggests improvements instead of overwriting.
/contextShows what is actually in context, including the list of Memory files that loaded. Use it to check that a file loaded.
/memoryLists every memory location (including files that don't exist yet), opens them in your editor, and toggles auto memory.
/doctor prompt-auditChecks your instruction files for conflicts, stale references, and bloat. Proposes edits; changes nothing until you agree (v2.1.283+; you have 2.1.300).

Part C: Do it

  1. In PowerShell, from lab\, start Claude and run /init. Read what it wrote. Notice what it couldn't work out from the files alone: Microsoft's rules about which PBIP files are safe to edit.

    cd $HOME\Desktop\Claude\claude-code-tutorial\lab
claude
/init

  2. Open CLAUDE.md in your editor and add a PBIP section yourself. Type it rather than paste it; writing it is part of the learning. Every line below comes from Microsoft's PBIP docs:

    lab\CLAUDE.md (append)## PBIP rules
<!-- Source: learn.microsoft.com/power-bi/developer/projects/projects-overview
     and .../projects-external-editing. Stripped before Claude reads this file. -->
- Semantic model = TMDL in `Contoso.SemanticModel/definition/`. Report = PBIR JSON in `Contoso.Report/definition/`.
- NEVER edit these (external edits unsupported): `definition.pbir`, `report.json`,
  `mobileState.json`, `semanticModelDiagramLayout.json`, `diagramLayout.json`.
- NEVER read or edit anything under `.pbi/` (`cache.abf`, `localSettings.json`): local cache, gitignored.
- Save every file as UTF-8 without BOM. Keep CRLF line endings.
- Before editing: ask me to Save in Power BI Desktop. After editing: tell me to click "Apply external changes".
- If `.pbi/unappliedChanges.json` exists, stop and ask me to apply pending changes first.

## Team conventions
- (write two of your own, e.g. where measures live, format strings, display folders, naming)

  3. Create CLAUDE.local.md next to it with one personal line, such as I'm advanced in DAX; keep explanations to one sentence. Add CLAUDE.local.md to .gitignore.

  4. Exit Claude (type /exit) and start it again so it reloads. Run /context and find CLAUDE.md and CLAUDE.local.md under Memory files. If one is missing, Claude can't see it.

  5. Positive test. Make sure Desktop has saved, then ask: Add a measure Avg Order Value = Total Sales divided by distinct orders, with a currency format string. Watch whether Claude asks you to save first and finishes by telling you to click Apply external changes. Click it in Desktop. The measure appears. 🎉

  6. Negative test. Ask: Tidy up diagramLayout.json so the tables sit in a neat grid. Claude should decline and point to your rule. Remember: it declined because it read a request. Nothing prevented the edit. That gap is what Lesson 5 closes.

  7. Commit CLAUDE.md, .gitignore, and the new measure. Run git status first and confirm that CLAUDE.local.md is not listed.

Part D: Retrieval practice

Close Part B in your head first. Answer from memory; the struggle is what makes it stick.

1. The whole team must know "all measures live in the _Measures table". Where does it go?

It's a team-wide convention for this project, so it goes in the project file and reaches teammates through git. User and local scope reach only you. Managed policy is org-wide and owned by IT.

2. You launch Claude in lab\Contoso.SemanticModel\. Both lab\CLAUDE.md and lab\Contoso.SemanticModel\CLAUDE.md exist. What happens?

Files from the launch directory and every directory above it are concatenated, from the root down. Nothing overrides; the nearest file is read last.

3. Your CLAUDE.md says "NEVER edit diagramLayout.json". Is Claude guaranteed to comply?

CLAUDE.md is context, not enforced configuration. A PreToolUse hook is what blocks an action whatever Claude decides. Capitals may help Claude notice a rule, but they guarantee nothing.

4. Your CLAUDE.md is getting long, so you split it into three files with @imports. What happens to context cost?

Imports help organisation, not context. To actually save context, use path-scoped rules (next lesson) or move content into a skill.

5. Claude is ignoring an instruction. Which command shows whether the file loaded this session at all?

/context lists the memory files that loaded. /memory lists every memory location, including files that don't exist yet, so it can't tell you what actually loaded.

6. Your personal Fabric dev workspace name matters only to you, only in this repo. Best home?

Just you, just this project, so it's local scope, gitignored. The user file would carry it into every project you open.

7. You have a 12-step "publish to the Fabric test workspace" checklist that you run weekly. Best home?

The docs say a multi-step procedure belongs in a skill, which loads only when you use it. In CLAUDE.md it would cost context on every request. Skills are Lesson 4.

Write it out: name the four CLAUDE.md scopes, where each file lives, and who it reaches. Then, in one sentence, explain why a CLAUDE.md rule can't guarantee that Claude never touches a file.

Managed policy: C:\Program Files\ClaudeCode\CLAUDE.md, whole org. User: ~\.claude\CLAUDE.md, only you, every project. Project: .\CLAUDE.md or .\.claude\CLAUDE.md, the team via git. Local: .\CLAUDE.local.md, only you, this project, gitignored.

CLAUDE.md is context that Claude chooses to follow, not configuration the harness enforces. A hard guarantee needs a PreToolUse hook.
